Software Development

What is the difference between a bug and an incident?

A bug is a defect in code or configuration that produces incorrect behavior. An incident is the customer-visible operational impact of one or more bugs or failures. For example, a retry loop is a bug; the resulting API outage is an incident.

How should I debug a problem systematically?

Reproduce the problem, establish the expected behavior, collect the smallest useful evidence (logs, metrics, inputs, environment), form a single hypothesis, test it, and verify the fix. Change only one variable at a time and record findings so they can be reviewed or shared.

What should a useful log entry contain?

Include a timestamp, severity, service/component name, correlation or request ID, event outcome, and enough context to investigate. Avoid secrets, access tokens, passwords, personal data, and unbounded payloads. Prefer structured key-value fields over prose-heavy messages.

What is the difference between unit, integration, and end-to-end tests?

Unit tests isolate a function or component. Integration tests verify interactions between components or with an external service. End-to-end tests exercise a complete user or system workflow, usually through public interfaces.

APIs and Web Services

What does HTTP 4xx versus 5xx mean?

A 4xx status indicates that the request cannot be completed due to client-side input or authorization (for example 400, 401, 403, or 404). A 5xx status indicates that the server failed while processing an otherwise valid request (for example 500 or 503).

How should I design a REST API response?

Use a clear resource URI, standard HTTP methods and status codes, stable JSON field names, and a consistent error shape. Document pagination, filtering, authentication, rate limits, deprecation, and versioning. Avoid returning implementation details or secrets in error messages.

What is idempotency and why does it matter?

An operation is idempotent when repeating it produces the same result or has the same effect. It is especially important for payments and retries: a client can safely repeat a request after a timeout or lost response. Use idempotency keys for operations that may create resources.

How do authentication and authorization differ?

Authentication establishes who a caller is. Authorization establishes what that caller may do. A valid token proves authentication but does not automatically grant permission to every resource.

Databases and Data

Why is a database query slow?

Common causes include missing indexes, inefficient joins or filters, large result sets, table bloat, lock contention, resource limits, or network latency. Use the query plan and database metrics before changing indexes or rewriting SQL.

What is a database transaction?

A transaction groups operations so they complete atomically: all changes commit together or none do under normal failure handling. Transactions should use the smallest isolation level and scope needed to preserve correctness.

What is the difference between backup and replication?

A backup is a recoverable copy intended for point-in-time restoration. Replication copies changes to another system to improve availability or distribute reads. Replication alone does not protect against accidental deletes or application-level corruption.

Git and Source Control

What is the difference between merge and rebase?

A merge adds a commit that joins histories and preserves branch context. Rebase moves commits onto a new base and creates a linear-looking history. Avoid rebasing commits that other collaborators rely on and follow the team workflow.

How do I recover a mistaken commit?

If the commit is not shared, reset or rebase can remove or rewrite it. If it is shared or production code is affected, prefer a new revert commit that reverses the changes. Preserve evidence and rerun tests.

What makes a good pull request?

Keep it focused, explain the problem and solution, link relevant issues, include test evidence, and note breaking changes or migrations. Small, reviewable diffs are easier to reason about and less risky.

Deployment and Operations

What is blue-green deployment?

Two environments run at once: one serves traffic and the other receives the new release. After validation, traffic switches to the new environment. The old environment remains available for a rollback.

What is observability?

Observability is the ability to understand system behavior from external evidence. It combines logs, metrics, traces, alerts, and dashboards so operators can answer questions during known and novel failures.

How should capacity be provisioned?

Baseline requirements with load testing and historical usage, then add safe headroom for spikes and failures. Autoscaling helps but requires sensible minimums, warm-up time, limits, and cost controls.

What is rollback?

Rollback restores a previously known-good application, configuration, or data state after a failed release. A complete rollback plan also defines database compatibility and customer-side cache or worker implications.

Security and Reliability

How should secrets be managed?

Use a managed secret store or environment configuration supplied at runtime. Never place secrets in source control, logs, tickets, screenshots, or build artifacts. Rotate exposed credentials promptly and grant only the permissions required.

What is least privilege?

Every person, service, build job, and network path should receive only the permissions needed for its authorized task. Review temporary grants and remove unused access.

How can a system tolerate dependency failures?

Use timeouts, bounded retries with backoff and jitter, circuit breakers, queues, fallbacks, and bulkheads where appropriate. Avoid retry storms and make partial degradation predictable.
